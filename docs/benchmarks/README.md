# Benchmarks

All of these tables are regenerated by make targets. CI checks the ladder,
the edges and the precision tables against the code at each commit; gas,
pi, the replays and the accrual are not diffed in CI.

- [`ladder.md`](ladder.md) / [`ladder.json`](ladder.json): **terminal precision.**
  Thirteen real calculations expressed as N identical steps (daily compounding,
  a square-root bonding curve, exp/ln round trips, an amortising loan, a
  running geometric mean, Black-Scholes d1 along a price path, a cumulative
  product of basis-point factors, compounding via one real-exponent pow,
  annual compounding, per-second accrual, continuous accrual, an option
  walking out of the money priced with N(d), and a decay chain measured as
  the share released), each for several documented inputs (87 in all), run through FP127 (deployed object
  and inline library), ABDKMath64x64, Solady, PRBMath SD59x18, ABDKMathQuad
  (binary128), Balancer LogExpMath, and the accrual formulas of Aave v3,
  Morpho Blue and Maker (which answer only the accrual scenarios their
  models describe), and FP256, the 256-bit float, for N = 1 to 10,000, against the same loop in exact
  arithmetic (mpmath, 300 digits) twice: from the exact parameters (`digits`)
  and from the parameters as the library received them (`digitsFormat`, the
  arithmetic alone). Each cell gives both digit counts, the signed error in
  ULPs, and gas per step measured inside the adapter; summaries give the
  median and range over the inputs; the `methodology` key defines every
  number. Produced by `make ladder` from
  `test/ladder/Ladder.t.sol`, which calls the same `LadderRunner` contract
  that is deployed on Sepolia, via `scripts/ladder/ladder.py`. Scenario
  parameters and rationale: `scripts/ladder/scenarios.json`; the floored parameters each library
  receives: `scripts/ladder/inputs.json`. The same runner
  is live on Sepolia (address in `contracts/deployments/Ladder.json`)
  (`contracts/deployments/Ladder.md`), and `liveMaxN` in the JSON says how
  far up the ladder a public RPC will execute each cell.
- [`edges.md`](edges.md) / [`edges.json`](edges.json): **the edges.** One call
  at the end of each domain, 139 probes over fifteen ops (ln near one, exp
  at both ends, tiny roots and products, per-second rates to a power,
  Uniswap's tick range, both Lambert branches, the error function and the
  normal tail), through every library, each cell either with its digits or
  with how the library had no answer: zero below its floor, a revert, an
  argument outside its word, or no way to compute the op. Produced by
  `make edges` from `test/ladder/Edges.t.sol` through the same `EdgeRunner`
  that is deployed on Sepolia; probes in `scripts/ladder/edges.json`, the
  encoded arguments in `scripts/ladder/edge-inputs.json`.
- [`sweep.md`](sweep.md) / [`sweep.json`](sweep.json): **per-op accuracy on
  random inputs.** Every FP256 op against the correctly rounded word and every
  FP127 op against the real truth, 1,500 to 20,000 seeded inputs each,
  with each op's gas and the share of inputs whose rounding test fell back
  to the second stage (`make sweep`).
- [`profile.md`](profile.md) / [`profile.json`](profile.json): **where the
  gas goes.** On the sweep's inputs: each op's gas (median, p99, max), its
  fallback rate, and the share of its gas spent in each named helper,
  measured by test-only probed copies of the libraries that are generated,
  run and removed (`scripts/fp127/gen.py --count-lib`, `--probe-lib`);
  and whether compiling the caller with `via_ir` closes the gap between the
  inline libraries and the Yul objects (`test/profile/ViaIr.t.sol`). `make
  profile`.
- **Replays: four exploits, bit-exact.** Each one reproduces the deployed
  arithmetic from integers pinned out of the attack transaction and asserted
  against the chain, then prices the decisive step again under the
  protocol's own fix, FP127, FP256 and exact rationals (`make replays`;
  `make replays-fetch` re-pins, read-only).
  - [`replay-resupply.md`](replay-resupply.md): Resupply, 26 Jun 2025. `1e36 / price` floors 0.5 to 0, and 1 wei of collateral borrows 10M reUSD.
  - [`replay-bunni.md`](replay-bunni.md): Bunni v2, 2 Sep 2025. 44 withdrawals take active USDC from 28 wei to 4 and liquidity falls 84%.
  - [`replay-balancer.md`](replay-balancer.md): Balancer V2, 3 Nov 2025. 17.988 is read as 17 in the osETH and wstETH pools, with the invariant's Newton solve measured on each ruler.
  - [`replay-balancer-v1.md`](replay-balancer-v1.md): Balancer V1, 31 Aug 2026. Five pools; rounding to nearest at raw token units, a case decided by direction, not precision.
- [`accrual-deployed.md`](accrual-deployed.md) / [`accrual-deployed.json`](accrual-deployed.json):
  **the accrual maths as deployed.** Aave v3 Core (v3.7.0) and Morpho Blue
  (v1.0.0, with the AdaptiveCurveIrm) run from submodules whose runtime
  bytecode is proven equal to mainnet (`make accrual-verify`), on stylised
  cases built from live parameter sets and on every reserve's and market's
  pending accrual at a pinned block (`scripts/accrual/survey.json`), against
  mpmath at 200 digits of the formula each protocol says it approximates,
  with each error split into series truncation and integer rounding, and
  FP127 / FP256 computing the same formula for contrast. `make
  accrual-deployed` from `test/accrual/DeployedAccrual.t.sol` via
  `scripts/accrual/accrual.py`. Not in CI (it needs solc 0.8.19 for the IRM).
- [`pi.md`](pi.md): **the same recipe, six grids.** Ramanujan's series for
  1/pi evaluated through each library's own sqrt, mul and div: FP127 reaches
  36 digits at five terms, FP256 39 (70 at nine), Quad 33, ABDK 17, Balancer, Solady and PRBMath 16. `make pi-compare`
  from `test/fp127/PiCompare.t.sol`.
- [`gas.md`](gas.md) / [`gas.json`](gas.json): gas for every FP127 op across
  an input ladder, for the Huff baseline, the Yul object, `FP127Caller`,
  `FP127Lib` and the five competitor libraries, and a second table on
  typical inputs (random, non-integer, no shortcut) for the transcendentals.
  The inline forms are the library call alone, timed inside the harness's
  entry point after its dispatch. `make bench`.
- [`gas256.md`](gas256.md) / [`gas256.json`](gas256.json): gas for every FP256
  op (object, inline, the same op in FP127Lib on the same value, and
  ABDKMathQuad), the same way. `make bench-fp256`.
- [`coverage.md`](coverage.md): every function of every comparison library
  mapped to the op it is benched against, or why it is not compared. An empty
  gas cell means only "not offered"; `rev` means offered but reverted on every
  input. The bench checks the harness against its list of calls.
- [`../fp256/precision.md`](../fp256/precision.md) / [`../fp256/precision.json`](../fp256/precision.json):
  correct bits of every FP256 op on the decoded values. `make test` then
  `make precision-report-fp256`.
- [`../fp127/precision.md`](../fp127/precision.md) / [`../fp127/precision.json`](../fp127/precision.json):
  correct bits of every op against mpmath over the committed vectors.
  `make test` then `make precision-report`.

Library versions: Solady v0.1.26, PRBMath v4.2.0, ABDK v3.2 (64.64 and
Quad), Balancer v3 LogExpMath and the Aave/Morpho/Maker formulas pinned in
`contracts/src/ladder/vendor/README.md` (the `versions` block in each JSON
records the exact tags and the FP127 commit). To rerun after a bump, update
the submodule or the vendored file, then `make bench ladder`.

## Reading the ladder

"Terminal precision" is the precision a calculation ends with after all its
steps, as opposed to the headline precision of one op. A WAD library keeps
about 60 fractional bits, 18 decimal digits; ABDK 64 bits. FP127 keeps 128.
The ladder shows the digits that survive N steps. Where a library reverts
at some N, the cell says so with the revert selector; that is a result,
not a gap.

The Huff-era fuzz sweep (`precision_distribution.json`, `fuzz_data.txt`
and the scatter plots) is gone; its single-op view is superseded by the
per-op precision table and the ladder.
