# FP256 in Yul

256-bit binary floating point for the EVM, release three (in the
repository; Sepolia carries release two until the next deploy). One `int256` per
value, the bit pattern of a float:

| bits | field |
|---|---|
| 255 | sign |
| 254..236 | biased exponent E, 19 bits, bias 262,143; valid 1..524,287 |
| 235..0 | fraction F; the significand is 2^236 + F, 237 bits |

value = (−1)^s · (2^236 + F) · 2^(E − 262143 − 236). Zero is the all-zero
word and the only word with E = 0; any other word with E = 0 is not a
number and every op reverts `OutOfRange` on it. There is no NaN, no
infinity, no subnormal and no negative zero: every valid word is a finite
number with one representation, equality is bit equality, and positive
words order as unsigned integers. Range 2^−262142 to just under 2^262145,
about 10^±78,900; 237 significant bits, about 71 decimal digits, at every
magnitude.

This is the second ruler. [FP127](../fp127/README.md) is a fixed point:
38 digits between 2^−128 and 2^127 and nothing outside. FP256 keeps 71
digits wherever the value sits, at the price of an exponent to align on
every add and a renormalisation on every result. The
[edges](../../../docs/benchmarks/edges.md) are why it exists.

## Files

| file | role |
|---|---|
| `FP256.yul.src` | the source of truth: Yul function bodies only |
| `FP256.yul`, `FP256Lib.sol`, `IFP256.sol`, `abi.json`, `ops.json` | generated by `scripts/fp127/gen.py --lib fp256` (`make gen-fp256`) |

The generator, its rules and the two-forms argument are FP127's; see that
README. The helpers `rev`, `absw`, `msb`, `mulg`, `divu`, `exp2frac` and
`log2poly` are byte-identical copies of FP127's, and `log2m` is FP127's
`log2g` after its normalisation.

## Rounding

Half up on the magnitude (ties away from zero), once per op. Every
rounding site is `normround`: the exact result is floored on a grid at
least as fine as half an ULP, then the first discarded bit is added. That
keeps every op odd-symmetric (`neg(add(a, b)) == add(neg a, neg b)`,
bitwise) and needs no sticky bit at the rounding site. Overflow (an
exponent above 524,287 after rounding) reverts `Overflow`; underflow
rounds to zero with the sign dropped.

## Ops

| op | semantics | reverts |
|---|---|---|
| `add`, `sub` | 18 guard bits, a sticky bit on the difference, one rounding; exact whenever representable | `Overflow`, `OutOfRange` |
| `mul` | the 474-bit product of the significands, one rounding | `Overflow`, `OutOfRange` |
| `div` | floor(ma·2^255 / mb) by two exact 2^128 stages, one rounding | `DivisionByZero`, `Overflow`, `OutOfRange` |
| `sqrt` | the integer root of the significand at 2^136 (Newton, corrected by squaring), one rounding; never overflows | `OutOfRange` for x < 0 |
| `exp` | 2^(x log2 e): the 512-bit product of the significand and log2 e in two words, split into the integer part and a fraction at 2^−254, 2^f from a 16-entry table and a degree-26 polynomial, one rounding; 1 + x + x²/2 floored exactly on the grid below 2^−118 (and at the x = a·2^−118 ties), one rounding; exactly one below 2^−238 | `Overflow` above about 181,705; zero below −181,700 |
| `ln` | (E − bias + log2(M/2^236)) ln 2: the exponent exactly, the mantissa through twelve reduction stages and a degree-17 polynomial at 2^−254, the sum scaled to fill a word, one product with ln 2 and one rounding; within 2^−8 of one, d = x − 1 exact and a 32-term series at 2^−254 | `OutOfRange` for x ≤ 0 |
| `log1p` | ln(1 + x) without a rounded 1 + x: below 2^−4, x times the ln series at 2^−254 (32 terms below 2^−8, 64 above); above, 1 + x exactly on a 2^−254 grid under its leading bit, the log2 kernel and one product with ln 2 | `OutOfRange` for x ≤ −1 |
| `expm1` | e^x − 1 without cancellation: below 2^−8, x times the 24-term series Σ x^k/(k+1)! at 2^−254; above, exp's split of x log2 e and its unrounded 2^f with the one subtracted on the same grid; −1 below about −176 | `Overflow` above about 181,705 |
| `erf` | below ½, x·(2/√π)·e^(−x²) times the all-positive series Σ (2x²)^k/(2k+1)!!; above, 1 − erfc; ±1 from \|x\| ≥ 13 | never |
| `erfc` | a product, never a difference, for x ≥ ½: e^(−x²)·g(x), g = e^(x²)·erfc from a Taylor series around 45 anchors on [½, 6] (one stored g(j/8) each, coefficients from g′ = 2xg − 2/√π) and a continued fraction scaled by x^k beyond; e^(−x²) from the exact 474-bit square, so the tail keeps 71 digits until it underflows near x = 427; 1 − erf below ½, 2 − erfc(−x) below zero | never |
| `normCdf` | Φ(x) = erfc(−x/√2)/2 with e^(−x²/2) from the exact square; the left tail keeps 71 digits until it underflows near x = −603; exactly one from x ≥ 13√2 | never |
| `lambertW0` | W e^W = x, W ≥ −1: FP127's seeds (the branch-point series in p = √(2(1 + e·x)) with 1 + e·x exact, x − x² + 3/2·x³, Winitzki), six Newton steps on the float ops (w·e^w = x up to 3, w + ln w = ln x above, so W reaches 181,700); within one ULP away from −1/e; near it the ten-term series below p = 2^−21 and Newton above, 218 bits at worst | `OutOfRange` below −1/e |
| `lambertWm1` | W ≤ −1 on [−1/e, 0): the series in −p or L − ln(−L) + ln(−L)/L, seven log-form Newton steps (no e^w; W reaches −181,700); as `lambertW0` near −1/e | `OutOfRange` outside [−1/e, 0) |
| `pow` | 2^(y log2 x): log2 x as a scaled word from the kernel (or the near-one series), its exact 512-bit product with y's significand split into the integer part and a fraction at 2^−254, then 2^f and one rounding; shortcuts for y ∈ {1, 2, ½, −1}; 0^0 = 1 | `OutOfRange` for x < 0, `DivisionByZero` for 0^negative, `Overflow` |
| `neg`, `abs`, `sign` | bit operations; −0 is 0 | `OutOfRange` |
| `cmp`, `lt`, `eq` | through a monotone key (negatives mirrored); `eq` is bit equality; results are plain integers | `OutOfRange` |
| `fromUint(x)` | exact below 2^237, one rounding above | never |
| `fromFP127(x)` | x / 2^128, exact when \|x\| has at most 237 significant bits | never |
| `toFP127(x)` | the nearest 127.128 word, half up; zero below 2^−129; −2^127 allowed | `Overflow` at or above 2^127 |
| `fromFixed18(x)` | the integer as a number (exact below 2^237), divided by 10^18 with one rounding | never |
| `toFixed18(x)` | the nearest 18-decimal word from the exact product M·10^18 | `Overflow` |

## Precision

`make test` runs every op over the committed vectors in
`test/fp256/vectors/` (generated by `scripts/fp256/oracle.py`: exact
rationals for the arithmetic and the conversions, so those references are
bit-exact, and mpmath at 300 digits for the transcendental ops) and writes
`docs/fp256/precision.json`; `make precision-report-fp256` renders
`docs/fp256/precision.md`. The arithmetic ops, `sqrt`, the comparisons and
the conversions are bit-exact at every vector, and so are `exp`, `ln`,
`log1p`, `expm1`, `erf`, `erfc` and `normCdf`: the kernels compute at 2^−254 with 512-bit products
(`scripts/fp256/generators/kernel254.py` fits them, models every op in
exact integers and reports the bits before rounding: 2^f within 2^−253,
log2 within 2^−250 absolute), so the one rounding at the end is the
correct one. The test has no ULP slack: the floor is 256 bits, the word
itself, for every op but `pow`.

Exact ties need care, because a kernel within 2^−250 cannot tell a value a
hair above a tie from one a hair below. A transcendental result of a
dyadic argument is never exactly a tie, but a truncated series can be:
1 + x + x²/2 is one whenever x = a·2^−118 with a odd, and the cubic that
breaks it is below the kernel's reach under 2^−84. `exp` takes those
inputs, and everything under 2^−118, through an exact floor of
1 + x + x²/2 on the 2^−254 grid (the cubic only breaks the tie) and one
rounding; release two's 1 + x(1 + x/2) rounded twice, and returned exactly
one for some x in (−2^−237, −2^−238). The series bands of `ln`, `log1p`
and `expm1` meet the same ties (x ± x²/2 when the exponent is even and the
lowest bit sits at 2^−(236 − u)/2), and their Horner floors land exactly on
the tie with the true value on the side that rounds up; tie vectors for
each are in the spec. `log1p` keeps its series up to 2^−4 so the log2
kernel's 2^−250 never meets a result small enough for it to matter.

`lambertW0` and `lambertWm1` iterate on the rounded float ops, so they
are within one ULP away from −1/e (235 bits at worst) but not correctly
rounded; near −1/e Newton loses log2(1/p) bits until the branch-point
series takes over, and the floor is 218 bits.

`pow` is held to one ULP (236 bits): t = y log2 x carries the kernel's
2^−250 scaled by |t|, and 7 of its 234 vectors sit one ULP from the
oracle. Correct rounding there needs a double-word log2 (about 2^−300).
Release one rode FP127's 2^−192 kernels and held 146, 149 and 123 bits.

## What changed from FP127's conventions

`pow(0, y)` with y < 0 reverts `DivisionByZero` (FP127 returns 0). The
comparisons return plain integers, not numbers. Everything else follows
FP127: the same three errors, the same generator, the same proof that the
object and the library agree on the full `int256` domain
(`test/fp256/Equivalence.t.sol`).
