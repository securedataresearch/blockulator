# FP256 in Yul

256-bit binary floating point for the EVM: 65 ops, every one correctly
rounded or exact, and the constant `PI`, from one source. Blockulator 2.2
deploys them as four objects by idea: FP256, the number; FP256E, the
elementary functions; FP256H, the hyperbolic functions; FP256S, the special
functions ([below](#four-objects)), live on Sepolia since 2026-10-22 as
FP256 v5, at the addresses in
[`contracts/deployments/FP256.md`](../../deployments/FP256.md). They are
evm osaka builds and need a chain with CLZ. Release four (Blockulator 2.1,
67 ops in FP256, FP256X, FP256X2 and FP256X3) and releases one to three
stay deployed.

One `int256` per value, the bit pattern of a float:

| bits | field |
|---|---|
| 255 | sign |
| 254..236 | biased exponent E, 19 bits, bias 262,143; valid 1..524,287 |
| 235..0 | fraction F; the significand is 2^236 + F, 237 bits |

value = (−1)^s · (2^236 + F) · 2^(E − 262143 − 236). Zero is the all-zero
word and the only word with E = 0; any other word with E = 0 is not a
number and every op reverts `OutOfRange` on it. There is no NaN, no
infinity, no subnormal and no negative zero: every valid word is a finite
number with one representation, equality is bit equality, and positive
words order as unsigned integers. Range 2^−262142 to just under 2^262145,
about 10^±78,913; 237 significant bits, about 71 decimal digits, at every
magnitude.

This is the second ruler. [FP127](../fp127/README.md) is a fixed point:
38 digits at 1, 8 at 10^−30, and nothing outside 2^−128 to 2^127. FP256 keeps 71
digits wherever the value sits, at the price of an exponent to align on
every add and a renormalisation on every result. The
[edges](../../../docs/benchmarks/edges.md) are why it exists.

## Chains: CLZ (Osaka) required

Every leading-bit count goes through one helper, `msb(x) = 255 - clz(x)`,
on the CLZ opcode (EIP-7939, Fusaka/Osaka, 5 gas), and `ctz` takes CLZ of
the lowest set bit; both are guarded so f(0) = 0. msb keeps its early
`leave`, so the optimizer leaves it a function (inlined at its 35 sites it
costs about 450 bytes). The four objects and
`FP256Lib.sol` all need it: compile the library with solc >= 0.8.31 and
`evm_version = "osaka"` (this repo pins 0.8.38), and use them only on a
chain that has CLZ. Results are the same words and reverts as release
four, which ran Solady's branchless log2 for msb (168 gas; about 14 now):
154 gas less per leading-bit count, so 150 to 1,300 less per op through
the object ([`docs/benchmarks/gas256.md`](../../../docs/benchmarks/gas256.md)).

Supported chains are those with CLZ, as of 2026-10-22 (each probed live;
dates and names are the networks' announced activations):

The objects deploy fine on a chain without CLZ (the init code only copies
the runtime), but there the opcode is invalid and every call that counts
leading bits fails and burns all the gas it was given. Probe a chain before
deploying to it or calling it: an `eth_call` with no `to` and the creation
code `0x60011e60005260206000f3` (PUSH1 1, CLZ, PUSH1 0, MSTORE, PUSH1 32,
PUSH1 0, RETURN) returns the word `0xff` where CLZ exists. `make probe-clz
RPC=<url>` runs it, and every `deploy-*` target runs it first and refuses
to send unless the answer is 255.

## Four objects

Each deployed object is one idea, and ops that share a kernel live together.
An export tagged `/// @object FP256E` (or `FP256H`, `FP256S`) goes into that
object, an untagged one into FP256: the generator gives each object only its
exports and their callees, its own interface and ABI, and the inline library
holds everything. The objects table in `scripts/fp127/gen.py` (name, library,
salt) is the one list the Makefile, `stdjson.py` and `deploy.py` read.

| object | the idea | ops | runtime | salt |
|---|---|---|---:|---|
| FP256 | the number | add, sub, mul, div, inv, sqrt, cbrt, hypot, gavg; neg, abs, sign; cmp, lt, eq, min, max, clamp; floor, ceil, round, frac; avg, dist, zeroFloorSub, lerp; mulDown, mulUp, divDown, divUp; fromUint, fromUintDown, fromUintUp, toUintDown, toUintUp, toIntDown, toIntUp, fromFixed18, toFixed18, toFixed18Down, toFixed18Up, fromFP127, toFP127: 43 | 10,333 | `FP256 v5` |
| FP256E | the elementary functions, on one exp/log kernel | exp, exp2, exp10, expm1, ln, log2, log10, log2Up, log1p, pow, powu, compound: 12 | 21,598 | `FP256E v5` |
| FP256H | the hyperbolic functions | sinh, cosh, tanh, atanh: 4 | 13,021 | `FP256H v5` |
| FP256S | the special functions | erf, erfc, normCdf, lambertW0, lambertWm1, factorial: 6 | 24,263 | `FP256S v5` |

**Why the hyperbolics have their own object.** They are elementary functions
on the same kernel and belong with FP256E by idea, but FP256E with them
measured 27,308 bytes, 2,732 over the 24,576 limit, and FP256S has under a
thousand bytes to spare. So FP256H carries its own copy of the exp/log kernel
at its own address. That costs bytes at deployment and nothing per call: a
call runs one object's code either way. The kernels' rewrite (below) took
FP256E to 21,598 bytes, 2,978 under the limit: still short of the hyperbolics,
so the four objects stay.

**The core's room goes to the basic ops.** Without the kernels FP256 is
about 10 KB, so its fast paths can spend bytes: `normtop`, where add, sub,
mul, div, inv, avg and fromFixed18 end, writes the word itself instead of
calling `pack` (41 gas less each); `toIntDown`, `toIntUp`, `toFixed18Down`,
`toFixed18Up` and `toFP127` read the word in place instead of through
`unpack` (67 to 70 less); `mulDown`, `mulUp`, `divDown` and `divUp` read
their words in place and round through `dirtop`, which knows the top bit of
mul's and div's significand as `normtop` does and writes the word itself
(265 to 281 less). Every result is bit-identical (measured inline, the
default pipeline; `docs/benchmarks/gas256.md` has the objects).

`pi` is not an op: `FP256Lib.PI` is the word nearest π,
`0x40000921fb54442d18469898cc51701b839a252049c1114cf98e804177d4c762`, which an
object caller can copy. `gcd` is gone; the integers it served are exact in
FP256, so a caller who needs it runs Euclid on `toUintDown` of each.

`make build-fp256` compiles the four, `make size-fp256` prints their sizes,
and `predict-fp256e`, `-fp256h`, `-fp256s` with their `deploy-...-sepolia`
and `verify-...-sepolia` mirror FP256's targets. Deployed 2026-10-22 on
Sepolia: FP256 `0xAa1f71B7B08d568379b28E1488c6B737a1C6eb52`, FP256E
`0x017F68A57dD53a6dF2043c24B712b287F9549AE2`, FP256H
`0xEfefa2B63A173d56F9db79C5dd8A607F4aA859A5`, FP256S
`0x73E8809F163d4358773cc5F25c134997B4b842F4`.

Release four (Blockulator 2.1, still live) split the same ops as FP256 (the arithmetic, exp, ln,
pow and the conversions), FP256X (erf, erfc, normCdf, Lambert W), FP256X2
(exp2, exp10, the logs, cbrt, the hyperbolics) and FP256X3 (the algebraic
ops, gcd, factorial, pi): where the bytes fit, not by idea, with the exp/log
kernel in three of them and the core at 64 bytes from the limit.

## The kernels

Every exp/log op runs on four kernels at 2^−254 (`scripts/fp256/generators/kernel254.py`
fits and models them; `minimax.py` is the Remez exchange and the
certificate). Blockulator 2.2 rewrote them after measuring what an EVM
kernel pays for (a throwaway harness, inline library, median gas): a
product through the `mulwu` helper cost 215 gas, the same high word written
in line 91, a one-word product 32, a 16-way switch 252 against 156 for four
binary tests, and a 512/256 division (`divh`) 393. So a multiplication saved
is worth about 90 gas, a table level about 250 and a division about four
products.

| kernel | release two | now | gas then → now |
|---|---|---|---:|
| `exp2frac`, 2^f | a 16-entry table, a degree-26 Chebyshev fit on [0, 1/16) | two 16-entry levels (r < 2^−8), the degree-19 minimax polynomial (sup norm 2^−270.7), Horner at 2^−255, 7 of 19 steps in one word; within 4.7 units | 5,295 → 1,483 |
| `log2m`, log2 of a mantissa | twelve multiplicative stages by 2^(1/2^k), a degree-17 fit; bounded at 37 units | two additive 16-entry levels by word-only reductions (one shift and one div by 16 + i or 256 + i, the table value added), y = w/(2 + w) by one `divh`, y·P(y²) with P the degree-12 minimax polynomial (2^−263.7); within 2.4 units | 5,810 → 1,653 |
| `ln1pseries`, `ln1pwide`, ln(1 + d)/d below 2^−8 and 2^−4 | the 32- and 64-term Taylor series | (ln 2/2)(1 − y)·P(y²), y = d/(2 + d) by one `divh` (2/(2 + d) = 1 − y): the same P below 2^−8, a degree-21 one (2^−266.5) to 2^−4; within 2.7 units, relative however small d is | 7,586 → 1,406; 15,099 → 1,867 |
| `expm1series`, (e^d − 1)/d below 2^−8 | the 24-term Taylor series | the degree-21 minimax polynomial on [−2^−8, 2^−8] (2^−271.5), signed Horner (one-word steps by `mul` and `sar`); within 1.6 units | 5,433 → 1,300 |

Every fit is a minimax polynomial, none a Taylor truncation. A step of
p_j = c_j + p_{j+1}·u whose error reaches the result times u^j runs in one
word, ((p >> a)·(u >> b)) >> (256 − a − b), when that error times u^j is
under 2^−9 units; the generator picks a and b and adds the excess (under
2^−6 units in all) to the bound. The candidates that did not pay or did not
fit: a third exp table level (1,465 gas, 1.5 KiB more, and FP256S, which
carries the kernels, has 313 bytes left), a minimax rational corrector for
exp, (A + zB)/(A − zB) by one `divh` (1,718 to 1,755: the division costs
more than the products it saves), two 32-entry log levels (1,679 for 1 KiB
more than two 16-entry ones at 1,702), and log2 straight from the reduced
w without the division (1,934).

## Rounding

**To nearest**, half away from zero on the magnitude, once per op, for every
op without a direction in its name. Every rounding site is `normround`: the
exact result is floored on a grid at least as fine as half an ULP, then the
first discarded bit is added. That keeps every op odd-symmetric
(`neg(add(a, b)) == add(neg a, neg b)`, bitwise) and needs no sticky bit.
Overflow (an exponent above 524,287 after rounding) reverts `Overflow`;
underflow rounds to zero with the sign dropped.

**Directed** (release four), for the token edge: a protocol converting a
value into token units must round toward itself. In the Balancer V1 replay
([`replay-balancer-v1.md`](../../../docs/benchmarks/replay-balancer-v1.md))
exact maths rounded to nearest still lost 7% per cycle. `Down` rounds toward
minus infinity and `Up` toward plus infinity, once, from the exact value:
`dirround` floors the magnitude and adds one ULP when any bit was dropped
(the product's low bits, the remainder `mulmod(ma, 2^255, mb)`) and the
direction points away from zero. A product or quotient below the format is
zero toward zero and the smallest number (2^−262142, with its sign) away
from it, so `mulUp` never rounds a positive amount to zero; `toUintUp` and
`toFixed18Up` charge one unit for any positive dust.

**Integral values** (#79): `round` takes halves away from zero, FP256's
tie rule (FP127's `round` takes them up); `frac` is x − floor(x) rounded
once, so a negative x within 2^−238 under an integer gives exactly 1.

## Correct rounding

Every op that is not exact by construction computes its fast value D (the
input of `normround`) as in release three, and a bound err on |D − exact|
in units of D's last bit. `rbad(D, err)` asks whether D ± err can round
differently from D: the bits under the 237-bit significand within err of
half an ULP. Only then a second stage recomputes the value in two words at
2^−510 (`(h, l)`, h a kernel word at 2^−254) and rounds that.

The second stage:

- `wexpm1`: e^r − 1 for r in [0, 1): z = r/2^24, e^z − 1 = z·T(z) by 19
  Horner terms (k = 20..12 in one word, k = 11..2 in two), then 24
  doublings E ← 2E + E² on the value scaled by 2^24, which keep its
  relative precision; within 2^−503. The doublings run in one loop without
  calls, each square with its cross term formed once (`wdbl`, bit for bit
  the same as `wmul`'s), so a call costs about 21k gas, not 27k.
- `wexp`: e^x = 2^k(1 + E), r = x − k ln 2 exact modulo 4 at 2^−510 with
  ln 2 in three words.
- `wlnw`: ln of a mantissa in [1, 2) by one Newton step from the kernel's
  value (within 2^−249): y0 − (e^y0 − m)/e^y0, the residual at 2^−510 and
  its quotient at 2^−502; within 2^−497.
- `wln1ps` and `em1w`: the series ln(1 + d)/d (⌈512/(−u − 1)⌉ terms for
  |d| < 2^(u+1): 128 at most, 64 below 2^−8, 14 at 2^−40) and (e^x − 1)/x
  in two words, relative, for the near-one bands.
- pow and compound: log2 x (or log2(1 + rate)) in two words, its exact
  three-word product with y's significand (or with n, any int256), split at
  2^−510, 2^f by `wexpm1`. ln, log2 and log10 hand the second stage the
  kernel's log2m they already have. powu, when its own bound misses, goes
  straight to pow's second stage (pow's looser bound would miss too);
  compound skips its fast value where its bound is sure to reach the
  rounding boundary (`compsure`: a per-second rate with |n log2(1 + rate)|
  from about 11,000 to 2^19).
- The error function: below y = 7 the all-positive series erf(y) =
  (2/√π) y e^(−y²) Σ (2y²)^k/(2k+1)!! in two words at a scale 2^−σ
  (σ = ⌊1.4434 ⌊y²⌋⌋ + 9), and 1 − erf for erfc (at most 74 bits of
  cancellation); from y = 7 the continued fraction 1/(2y + 2/(2y + 4/(2y +
  …))) (x and k for normCdf), numerator and denominator by two scaled
  recurrences of depth 1700/⌊|x|⌋ + 28 (2404 for normCdf): truncation below
  2^−402 from y = 7 to 430 (`bounds.py`).
- Lambert W, seed → fast → safe, no series. Near −1/e (1 + e·x below 1/8)
  the unknown is q = 1 + W on Φ(q) = (q − 1)e^q + 1 = 1 + e·x, with 1 + e·x
  exact in two words: the seed p·S(p), p = √(2(1 + e·x)) by the integer
  square root and S = (1 + W)/p (one analytic function on both branches,
  W−1 at −p) by a degree-16 Chebyshev fit on [−½, ½] (`lwsp`, relative
  error 2^−44.9 on 20,001 points, the constant term exactly 1, certified by
  `bounds.py`); then one sixth-order reversion step (`lwq510`) with e^q − 1
  from the core's wide exp kernel (`wexpm1` for W0, `wexpr(1, −1, |q|)` for
  W−1, within 2^−503 absolute, which is the relative precision the residual
  needs): Φ = q − E1(1 − q) (W0) or |E1|(1 + |q|) − |q| (W−1) wide, τ =
  (Φ − y)/(q²e^q) from the exact difference's top word, q̃(1 − τ(1 + b₁τ +
  … + b₅τ⁵)) with the b_k polynomials in q from the reversion. The error is
  5 units of 2^−254 whatever q (2^−503/(q·e^q) from the kernel, under a unit
  down to y = 2^−492, plus the roundings), so the branch point costs no
  precision and W = −1 ± q is exact. Elsewhere a seed from a crude
  logarithm (`lnc0`, a degree-3 fit, 2^−10.8) — x(1 − x + 3x²/2) for |x| <
  ⅓, Winitzki's L(1 − ln(1 + L)/(2 + L)) for x ≥ 1/8, L − ln(−L) + ln(−L)/L
  for W−1 — then fourth-order log-form steps at 2^−126 (`lwf128`, one to
  three) on the table-driven logarithm `lnc` (six reductions by 2^(1/2^k)
  as `log2m`'s, then 2·atanh(s)/s by a degree-7 fit, 2^−139.5) until one
  starts within 2^−18, and one at word precision (`lwlog`, the series
  reversion w(1 − u + uv/2 − uv²/2 + u²v/3) with u = f/(1 + w), v =
  u/(1 + w), the logarithm of the ratio of the significands by the log2
  kernel) with the bound 2·(1.01·du + 5) + 1, du = 1 + 32·2^254/|h|, and
  `rbad`. On a miss one log-form Newton step at 2^−510, w − (w +
  ln(|w|/|x|))·w/(1 + w). W and x share a sign, so the form holds for every
  x ≠ 0, and the ratio's one wide ln keeps the correction's relative
  precision down to the smallest x. The a-posteriori residual bound of the
  literature review (|w̃ − W| ≤ |f̃|·|w̃|/(|1 + w̃| − δ)) is what `lwlog`'s
  bound is; near −1/e the change of variable to q removes the 1/(1 + W)
  amplification, and the wide kernel's two words are the "adaptive
  precision" for every q at once.
- `exp2` and `exp10`: x or x log2 10 (three words) split at 2^−510 and 2^f
  by `wexpm1`, as pow's (`pow2w`).
- `log2`: pow's wide log2 (`wlog2`: the wide series near one, wln off it).
  `log10`: u log10 2 in three words plus ln(mantissa) log10 e (wln, then a
  wide product), or the wide ln series times log10 e near one.
- `sinh` and `cosh` from 1/2: e^|x| = 2^k (1 + E) by `wexp` and e^−|x| by
  `wrecip`, summed or subtracted in two words; below 1/2 `sinh` is x times
  sum x^2k/(2k + 1)! in two words. `tanh`: (1 − w)/(1 + w) with w =
  e^−2|x| by `wexp`, or the two series' quotient below 1/2. (The fast
  paths below 1/2 compose sinh and tanh from expm1's one-word machinery,
  and atanh below 2^−6 from log1p's; only the second stages keep a
  series of their own.)
- `atanh`: below 2^−4, x sum x^2k/(2k + 1) in two words; above, (uu1 −
  uu2) ln 2 plus wln of the exact mantissas of 1 + |x| and 1 − |x|, three
  words, halved in the one rounding.

Exact by construction: `cbrt` (the floor of the cube root of the
significand scaled to 714 to 716 bits, by Newton with precision doubling from a
seed in the bits and an exact three-word cube at the end), `gavg` and `hypot` (the floor of the square root of the
exact 474-bit product or sum of squares, floored only on a grid far under
the root's, so hypot's Pythagorean ties, which exist, round away from zero),
`lerp` (the exact a + t (b − a), below), `avg`, `dist`, `zeroFloorSub`,
`inv` (one rounding of an exact sum, difference or quotient), `min`, `max`,
`clamp`, `round`, `log2Up` (exact values) and `factorial` (exact while n!'s odd part fits
512 bits, so every exact tie; a 512-bit running product within 2^−500
above, checked against the exact factorial at every n of its domain).

`lerp` sums its three exact terms, a, t b and −t a, in a 1,024-bit window
under the largest. A term whose last bit falls under the window enters as
its floor; with one such term the floor of the sum is exact and lies at
least 544 bits under the sum (or the other two cancel exactly and the term
is the value); two such terms lie more than 546 bits under the third, which
fixes the result up to the sign of their sum. The window is four words of
memory just past the free memory pointer, which lerp reads and never moves
(memory-safe temporary memory), and the three terms, computed once, are
the fifteen words after it (sign, magnitude, last-bit exponent and top
position each); it is the one op that uses memory beyond the scratch
space.

pow, compound and powu compute exact ties exactly: when x^y has at most 238
significant bits (y = n/2^j with j ≤ 7 and n ≤ 150, the odd part of x a
perfect 2^j-th power: `powtie`; the odd part of 1 + rate for compound:
`onepexact`) the power is formed as an integer and rounded once. For the
other functions an exact tie cannot occur where a theorem says so: e^x, ln x
and W(x) are transcendental at every dyadic x other than 0 and 1
(Lindemann–Weierstrass). For erf, erfc and Φ none does; a tie would need a
dyadic value of exactly 238 bits.

`scripts/fp256/generators/bounds.py` recomputes each D as the Yul does (the
kernel254.py and erf256.py models) against 120-digit truth: no measured
error reaches 0.79 of its bound (pow's, where the shift's floor 2^sh meets 2|u|). An input misrounds only if its exact value lies
within the last column's distance of a tie: for a value without structure,
a chance of about twice that distance per input, 2^−116 at worst (next to
Lambert W's branch point). None is known.

## Typed API

`FP256Type.sol` is opt-in: `type FP256 is int256`, with `+ - * /`, unary
`-` and `< > <= >= == !=` bound globally, and every other op attached, so
`x.exp()` and `a.mulUp(b)` work. The comparisons are `lt` and `eq` read as
bools, so a word that is not a number reverts `OutOfRange()` in every one,
as in the library; `cmp` stays attached. Each function is a pure free
function that only re-types its arguments, so the words and reverts are
`FP256Lib`'s. Conversions: `FP256.wrap` / `unwrap` (or `fp256(raw)`, as
PRBMath's `sd()`), `fp256FromWad(uint256)` and `toWadDown` / `toWadUp` for
unsigned WADs, `fp256FromFixed18` and `toFixed18*` for signed ones,
`fp256FromUint*`, `fp256FromInt`, `toUint*` / `toInt*`, the constants `ONE`
and `PI`, and the typed FP127 ↔ FP256 pair: `y.toFP127()` and `toFP256(x)`
(attach the latter with `using {toFP256} for FP127;` to write `x.toFP256()`).
Names that take a plain integer carry the prefix, so both type files import
into one scope; alias `ONE` and `PI` there (`import {ONE as ONE127} ...`).

```solidity
import {FP256, ONE, fp256FromWad, fp256FromInt} from "fp256/FP256Type.sol";
import {FP127} from "fp127/FP127Type.sol";

FP256 b = fp256FromWad(1.5e18) * ONE.exp();  // 1.5e; * is FP256Lib.mul
bool between = b > fp256FromInt(4) && b < fp256FromInt(5);
uint256 charged = b.toUintUp();              // 5, ceiled
FP127 n = b.toFP127();                       // the nearest 127.128 word
```

`make typed` (part of `make test`) fuzzes every typed function against the
raw call, result and revert data byte for byte, and compares the gas of one
small contract per op in each form. Through the IR (`via_ir = true`) every
op costs exactly the same. Under the legacy pipeline the wrapper is one more
internal call, 36 to 56 gas.

## Precision

`make test` runs every op over the committed vectors in
`test/fp256/vectors/` (generated by `scripts/fp256/oracle.py`: exact
rationals for the arithmetic, the conversions and the directed ops, exact
powers for the ties of pow, compound and powu, mpmath at 300 digits for the
rest) and writes `docs/fp256/precision.json`; `make precision-report-fp256`
renders [`docs/fp256/precision.md`](../../../docs/fp256/precision.md). Every
op is held to the word itself at every vector, ties included: pow(c, 3),
pow(c², 3/2), powu(−c, 3) and compound(c − 1, 3) for c = 2^79 + 1, whose
cube has exactly 238 bits, and 3^150.

`make sweep` ([`docs/benchmarks/sweep.md`](../../../docs/benchmarks/sweep.md))
runs 364,658 seeded random inputs through the ops, each compared with
the correctly rounded word: 0 misrounded (`factorial` at every n of its
domain). The first 4,000 inputs of each
correctly rounded op go again through a test-only copy of the library whose
rounding test always fails, so every result comes from the second stage: 0
misrounded there too.

Exact ties in truncated series need care: 1 + x + x²/2 is a tie whenever
x = a·2^−118 with a odd, so `exp` floors 1 + x + x²/2 exactly on the
2^−254 grid below 2^−118 (the cubic only breaks the tie). The near-one bands
of `ln`, `log1p` and `expm1` meet the same ties (x ± x²/2), and their
remainder x³/3 is at least 2^−236 ULP there, well inside what the second
stage resolves.

## What changed from FP127's conventions

`pow(0, y)` with y < 0 reverts `DivisionByZero` (FP127 returns 0). The
comparisons return plain integers, not numbers. #79's ops keep FP127's names
and signatures with float semantics: `round` takes halves away from zero
(FP127: up), `frac` can return 1 (above), `log2Up` returns a number,
`factorial` runs to 20,366 (FP127: 33), and `lerp`, `avg`, `dist`, `hypot` and `gavg` round once from the exact value
instead of after each step. Everything else follows
FP127: the same three errors, the same generator, the same fuzzing of the
objects and the library for agreement across the full `int256` domain
(`test/fp256/Equivalence.t.sol`), and the directed ops carry the names
FP127's release five uses (mulDown, mulUp, divDown, divUp, toFixed18Down,
toFixed18Up).
