deterministic-deployment proxy, so the same source at the same compiler
settings lands at the same address on every chain that proxy exists on.
The machine-readable copy of this record is `FP127.json` beside this file;
`FP127.sepolia.receipt.json` is the raw transaction receipt.

Version 8 (2026-10-28, Blockulator 3.0) has the same 53 ops and returns the same word as versions 6 and 7 on every
op; `factorial`, `compound` and the erfc tail take new paths. `factorial` reads its 34 values from a table, two to a word: about 400 gas at every n
(v6 and v7 multiplied: 190 to 1,918). `compound` for |n| ≥ 16 takes n log2(1 + rate) from the one-word log and 2^t
through `pow2t` (sweep median, p99, max: 9,245, 10,913, 33,268 → 3,360, 9,344, 41,484). erfc for 4 < x ≤ 9.5 is
e^(−x²) times a degree-43 minimax polynomial in place of the continued fraction: 7,650 gas at every x of that tail,
and the maximum over erf, erfc and normCdf falls from 35,352 to 20,746. The object is 23,797 bytes (v7: 20,603).
Version 7, deployed the day before, is superseded before mainnet; it stays deployed and verified and is recorded
below. The ladder's version 13 `LadderFP127` calls version 8. See `CHANGELOG.md`.

Version 7 (2026-10-27) returns the same word as version 6 on every op and costs less: `exp` is
on three table levels and a minimax corrector, and `div` on one exact core (typical inline gas `exp` 5,360 → 2,716,
`exp2` 5,687 → 2,668, `div` 649 → 412). The object is 20,603 bytes (v6: 21,858). The ladder's version 12
`LadderFP127` calls it.

Version 6 (2026-10-22, Blockulator 2.2) has 53 ops: `pi(terms)` became the
constant `FP127Lib.PI` (the word nearest π) and `gcd` was removed. It is the
first CLZ build (evm osaka): it runs only on chains with EIP-7939, listed in
`README.md` beside this file. Every other op returns the same word as
version 5; the gas falls (sweep medians, v5 → v6: `ln` 3,410 → 1,934,
`pow` 6,121 → 3,375, `cbrt` 6,019 → 1,948, `cosh` 10,651 → 5,207,
`lambertWm1` 23,977 → 11,101, `lambertW0` 18,607 → 11,308) from the one-word exp/log kernels by table and minimax polynomial,
precision-doubling Newton for `sqrt`, `div`, `inv` and `cbrt`, the
hyperbolics on the exp/log kernels, Lambert W without series and CLZ for
the leading bit. `sinh` is the one op that got dearer (median 2,284 →
5,262), since its series below 1 went. See `CHANGELOG.md`. Versions 1 to 7
stay deployed and verified and are recorded below; the ladder's version 10
and 11 adapters call version 6.

address = keccak256(0xff ++ proxy ++ salt ++ keccak256(initCode))[12:]. There
are no constructor arguments, so the init code is the artifact's
`.bytecode.object` unchanged.

## Reproduce the bytecode

```sh
make build                              # generates FP127.yul and compiles it
uv run scripts/fp127/stdjson.py check   # solc standard-json (language Yul) == Foundry artifact
make predict                            # the address above, from the artifact alone
uv run scripts/fp127/stdjson.py onchain https://ethereum-sepolia-rpc.publicnode.com 0x466eCEde5Dc25189AD9ED999d0B4D41Cb022510B
```

The last command fetches the live runtime and compares its keccak256 with
the artifact's. That comparison, not an explorer badge, is the proof that
what is on chain is what is in this repository.

## Gas note

Sepolia is on the Amsterdam fork, where depositing contract code costs
about 1,550 gas per byte rather than 200 (measured: a 256-byte deposit
estimates at 615k gas, a 6,512-byte one at 10.34M). Forge 1.7.1's local
EVM still uses the old schedule and estimated 2.14M for this transaction,
which ran out of gas inside the proxy's CREATE2 (tx
`0xe4d91708…896d55`). `make deploy-sepolia` therefore sends the proxy call
with an explicit limit (`DEPLOY_GAS`) instead of trusting the estimate. The
limit was 20M until version 5, whose 19,863 bytes need about 31M: its first
send reverted out of gas, and the limit is now 40M. Every deploy target
rejects a receipt with status 0 before it replaces the previous one.

## Explorer verification

Etherscan's verification API accepts only Solidity (single file or
standard-json) and has no path for a Yul object, so Etherscan shows the
contract as unverified. Sourcify supports Yul and Blockscout's verifier
accepts standard-json with `language: Yul`; both receive the exact input
that `stdjson.py check` proves reproduces the artifact
(`make verify-sepolia`).

## Trust model

The object has no storage, no owner, no upgrade path and no selfdestruct;
it reads calldata and returns a word or reverts with one of three custom
errors. A CREATE2 deployment of such a contract is immutable by
construction. There is nothing to freeze after an audit and nothing to
register in an append-only list, because the address already commits to
the bytecode: anyone can recompute it from the source and the salt.

A new version is a new source, a new init-code hash and therefore a new
address, published here with a new salt string. Nothing can change the
code behind an address that has been published.

## Other chains

The proxy exists on mainnet and most L2s. Running `make deploy-sepolia`
with a different RPC (and chainId in the Makefile targets) lands the same
bytecode at the same address there. The address is recorded here only for
the chains it has actually been deployed to.

Version 5 (2026-10-21) has 55 ops. It was the FP127 of Blockulator 2.1 and
stays live and verified; the ladder's version 9 adapters call it. Every
transcendental returns the nearest word (on the random-input sweep v4 was
off by up to 4.8e34 ULPs in `pow` and 4.0e32 in `exp`); `pow` at extreme
exponents is the one exception, within 2^-299 (1 + |y|) relative. It adds
the directed ops `mulUp`, `mulDown`, `divUp`, `divDown`, `toFixed18Up` and
`toFixed18Down`; `mul`, `div`, `sqrt` and `toFixed18` return the same words
as version 4. The domain ends round to nearest (`exp` returns 0 below -90,
`tanh` is ±1 from 46), and the object dispatches by binary search on the
selector.
